# Siberian Detailing

Одностраничный сайт и серверная система онлайн-записи для детейлинг-студии.

## Запуск

Требуется Node.js 22.5 или новее. Внешние npm-пакеты не нужны.

```powershell
$env:ADMIN_PASSWORD='замените-на-надежный-пароль'
node server.js
```

После запуска:

- сайт: `http://127.0.0.1:3000`
- админ-панель: `http://127.0.0.1:3000/admin`

Если `ADMIN_PASSWORD` не задан, сервер создаст временный пароль и напечатает его в терминале. Он изменится после перезапуска.

Проверка синтаксиса:

```powershell
npm.cmd run check
```

## Переменные окружения

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `ADMIN_PASSWORD` | Постоянный пароль администратора | временный случайный пароль |
| `HOST` | Адрес прослушивания | `127.0.0.1` |
| `PORT` | Порт сервера | `3000` |
| `DB_PATH` | Путь к SQLite-базе | `data/siberian-detailing.db` |
| `BUSINESS_TIMEZONE` | Часовой пояс расписания | `Asia/Novosibirsk` |
| `TELEGRAM_BOT_TOKEN` | Токен бота для уведомлений | отключено |
| `TELEGRAM_CHAT_ID` | ID чата для уведомлений | отключено |

Для доступа из локальной сети установите `$env:HOST='0.0.0.0'`. Для публикации используйте HTTPS reverse proxy и не храните секреты в репозитории.

## Что хранится в базе

SQLite автоматически создаётся при первом запуске. В ней находятся:

- заявки клиентов и их статусы;
- индивидуальные настройки свободных интервалов;
- серверные административные сессии.

Слот уникален по дате и времени. Одновременные попытки записи не создадут дубликат: сервер вернёт HTTP `409`.

## API

Публичные методы:

- `GET /api/config` — услуги, классы автомобилей и период записи;
- `GET /api/slots?date=YYYY-MM-DD` — актуальные свободные интервалы;
- `POST /api/bookings` — создание заявки;
- `GET /api/health` — состояние сервера и базы.

Административные методы требуют HttpOnly-сессию, а изменения дополнительно защищены CSRF-токеном:

- вход и выход администратора;
- статистика и фильтрация заявок;
- изменение статусов и удаление заявок;
- просмотр, изменение и сброс расписания.

## Telegram-уведомления

Создайте бота через BotFather, добавьте его в нужный чат и перед запуском задайте:

```powershell
$env:TELEGRAM_BOT_TOKEN='токен-бота'
$env:TELEGRAM_CHAT_ID='идентификатор-чата'
$env:ADMIN_PASSWORD='надежный-пароль'
node server.js
```

Новая запись сохранится в базе независимо от доступности Telegram. Ошибка уведомления не отменяет заявку.

## Перед публикацией

Проверьте юридический текст политики обработки персональных данных, настройте HTTPS и регулярное резервное копирование файла базы.
